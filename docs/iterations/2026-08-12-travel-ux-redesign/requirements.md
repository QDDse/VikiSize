# 旅行体验改版需求

## 目标

让用户在手机上用最少步骤完成三个核心任务：

1. 收藏想去的地点。
2. 把多个地点排入某一天并调整顺序。
3. 在出行时快速找到下一站、交通信息和导航入口。

## 设计方向

- 视觉语言：克制、轻盈、地图导向，使用森林绿作为唯一强调色。
- 设计变化：中等。保留现有页面结构和导航名称，重组旅行页面内部层级。
- 动效：低到中等，只使用按压、选中和轻微位移反馈。
- 信息密度：中等偏高，但一次只突出当前日期和当前行动。
- 形状规则：卡片使用 13-17px 视觉圆角；操作按钮可使用全圆角。

## P0 验收标准

- 旅行主页顶部能显示总天数、总节点、待预约数和预计花费。
- 日期标签同时显示 Dn、日期和地点数。
- 时间线明确显示时间、顺序、地点、标签、备注和下一段交通。
- 点击地图标记能选中对应时间线节点，节点 ID 不发生映射复制。
- 用户可从地图选择地点并保存 GCJ-02 坐标。
- 用户可多选待安排地点，并批量加入同一天。
- 用户可按坐标距离整理当天路线。
- 路线整理必须保留第一站，并在坐标缺失时拒绝自动重排。
- 节点快捷菜单支持编辑、导航、复制、上移、下移和删除。
- 访客仍然只读。
- 原有 localStore 和云函数领域边界不变。

## P1

- 节点跨日期拖放。
- 使用路网 API 计算步行、驾车和公共交通时间。
- 路线整理允许锁定预约节点和固定时刻。
- 旅行执行模式显示当前站、下一站、延误和一键导航。
- 旅行凭证集中查看。

## P2

- 攻略链接/图片/文字解析。
- 附近地点推荐。
- 天气与营业时间提醒。
- 离线旅行包。
