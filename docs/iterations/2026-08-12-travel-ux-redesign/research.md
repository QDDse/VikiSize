# 旅行体验竞品调研

## 结论

VikiSize 不应完整复制某一个产品。最适合小程序 MVP 的组合是：

- 用圆周旅迹的“地点库 -> 批量排期 -> 路线整理 -> 地图查看”作为规划主循环。
- 用 Wanderlog 的日程与地图同源、拖动排序、预算和协作理念补强多人规划。
- 用 Tripsy / TripIt 的执行期信息聚合思路，逐步增加预订、凭证、天气、离线和提醒。
- 暂不复制社区内容流、订票交易、复杂 AI 对话或旅行足迹社交。

## 产品对比

| 产品 | 最值得学习 | 不适合当前版本 |
| --- | --- | --- |
| 圆周旅迹 | 链接/图片/文字攻略导入、地点收藏、自动规划、每日路线地图、多人编辑、附近推荐 | AI 导入需要内容解析服务和合规评估；精选内容需要持续运营 |
| Wanderlog | 地图与列表同源、拖放排序、路线耗时/距离、预订整合、预算分摊、离线、多人实时协作 | 功能密度较高，直接照搬会让小程序变重 |
| Tripsy | 航班/住宿/活动聚合、天气、时区、通知、附件、日历同步、旅行统计 | 深度依赖系统能力和第三方数据源 |
| TripIt | 通过邮件自动整理预订、离线查看确认信息、登机牌和文件集中管理 | 更偏预订后的行程管理，不擅长灵感收集和共同规划 |
| Tripomatic | 地点探索、预计步行距离、AI 日程、离线地图、主题地图 | 地点内容库和地图数据成本较高 |
| 穷游行程助手 | 自动优化、相邻景点距离、行程 PDF、记账和打包清单 | 产品交互相对传统，不作为视觉主参考 |

## 圆周旅迹为什么适合作为主参考

圆周旅迹把旅行规划中最麻烦的整理工作压缩成四步：

1. 从攻略或搜索中收集地点。
2. 在“我的地点”中筛选。
3. 批量加入某天行程。
4. 自动规划顺序，并在地图中检查路线。

这与 VikiSize 已有的 candidatePlaces -> travel nodes -> timeline/map 数据模型高度一致，能在不推翻领域模型的情况下快速提升体验。

## 本轮实现边界

本轮直接实现：

- 地图选点，保存真实坐标。
- 地点库的待安排/已安排视图。
- 多选地点后批量安排到同一天。
- 基于坐标的当天路线距离整理。
- 地图标记、选中节点和时间线共用同一节点 ID。
- 节点长按/更多菜单，提供编辑、导航、复制、移动和删除。
- 更适合移动端的时间线、日期导航、固定快捷操作栏。

后续实现：

- 从小红书、公众号、图片和文本导入攻略。
- 路网级路线优化和真实交通时间。
- 节点跨日期拖放。
- 天气、营业时间、附近推荐。
- 预订邮件/截图识别和凭证中心。
- 弱网与离线旅行包。
